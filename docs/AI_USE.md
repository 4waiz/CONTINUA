# CONTINUA — AI use

Where machine learning and AI appear in this project, and where they
deliberately do not.

---

## 1. The one hard rule

**No LLM is in the real-time routing loop, and none may be added to it.**

Every routing decision is made by one of two things:

| Predictor | What it is | Latency |
| --- | --- | --- |
| `heuristic-trend-1.1` | Least-squares trend extrapolation on RTT, loss and coverage, with fixed thresholds | microseconds |
| `learned-logistic-<version>` | 13-feature logistic regression, ~13 multiply-adds and one sigmoid | microseconds |

Both are deterministic, inspectable, and small enough to reason about by hand.
An LLM would be non-deterministic, orders of magnitude slower than the 3-second
prediction horizon, impossible to calibrate, and impossible to audit per
decision. There is no code path through which one could be invoked from the
controller.

The `predictors.py` module has exactly three implementations —
`NullPredictor`, `HeuristicPredictor`, `LearnedPredictor` — and `make_predictor`
can only return one of those.

---

## 2. The learned model

A logistic regression predicting one binary event: will the carrying path
violate an application threshold within the horizon.

Full details, including performance, calibration and limitations, are in
[`docs/MODEL_CARD.md`](MODEL_CARD.md). The essentials:

* Trained on synthetic data generated by this project's own simulator.
* Split by **whole run and scenario family**, never by row.
* Labels computed **offline** from recorded runs; **no future information is a
  runtime feature**, and a test enforces the feature allow-list.
* **Not calibrated** (mean absolute calibration error 0.136), so its output is
  reported as an uncalibrated *score* and never labelled a probability.
* Falls back to the heuristic if the artefact is missing or malformed, and
  `GET /api/health` reports which is active.

## 3. What is *not* AI here

Called out because these are easy to overstate:

* **The simulator** is a discrete-time queueing model. No learning.
* **The controller state machine** is hand-written rules with hysteresis and a
  minimum dwell time. No learning.
* **The application-aware policy** (duplicate control when at risk, adapt video,
  defer bulk) is hand-written. No learning.
* **`app_health_v1`** is a fixed weighted mean, documented in
  `docs/METRICS.md`. Not a learned score.
* **The coverage model** is geometry from a JSON file.
* **The 3D scene** is procedural geometry and hand-authored Blender assets.

The only learned component in CONTINUA is the link-violation predictor.

This codebase was written with substantial assistance from an AI coding
assistant (Claude), used for implementation, refactoring, documentation and

What that does **not** change:

## 5. Synthesised narration in the demo video

The video's voice-over is **synthesised speech**, produced locally by the
Windows speech API (`System.Speech.Synthesis`, voice "Microsoft David Desktop",
en-US) through `scripts/speak.ps1`. This is stated here because a viewer has a
right to know they are not listening to a person.

What that involved, precisely:

* **Local only.** Synthesis runs on this machine, in-process. No audio, text or
  identifier left the host. No external service was called and no API credits
  were purchased.
* **No voice cloning and no imitation.** The voice is a generic system voice
  that ships with Windows. No sample of any real person was used, and the
  narration does not present itself as any named individual.
* **The script is human-authored.** `video/narration.md` is the authority;
  every sentence in it traces to a row in `docs/VIDEO_CLAIMS.md`. Synthesis
  turns that text into audio and does nothing else — it does not write, edit or
  summarise.
* **Timing is measured, not assumed.** `scripts/build-narration.mjs` measures
  each synthesised line with `ffprobe` and fails the build if a line cannot fit
  its cue window, so the subtitles and the audio cannot drift apart. The first
  draft of the script failed this check on eight of fourteen lines and was
  rewritten.
* **The subtitles are the same text.** The `.srt` is generated from the same
  timeline entries as the audio, so a viewer reading rather than listening gets
  exactly what was spoken.

Nothing else in the video is generated. The 3D vehicle, the world, the caption
cards and the interface are all this repository's own work, and every figure on
screen is read from a recorded run.

## 6. Ethical and practical notes

* **All data is synthetic.** No personal data, no real user traffic, no operator
  measurements. Nothing was scraped and nothing was collected from anyone.
* **The vehicle is unarmed** and the scenario is emergency-response / industrial
  inspection. The project does not model weapons, targeting or surveillance of
  people.
* **The model's transferability is unevaluated.** It was trained on this
  simulator and should be assumed not to generalise to a real network. Its
  strongest feature (`coverage`) has no real-world counterpart as implemented.
* **Automation bias is a real risk** with a system like this. It is mitigated
  here by recording, for every action, the observations it was based on, the
  policy version, the predictor identity and a reason written at decision time —
  all visible in the Decision Log. An operator can always ask *why*, and get an
  answer that was not reconstructed after the fact.
* **Failure is shown as failure.** When every path is gone, the system reports a
  genuine outage and a simulated safe-stop rather than implying software can
  create connectivity that does not exist.
