# CONTINUA — asset manifest

Every asset in this project is generated by a script in this repository. There
are no purchased, downloaded or third-party models, textures or HDRIs.

## 1. Licence and provenance

| Asset class | Source | Licence |
| --- | --- | --- |
| Rover, world props | Generated by `scripts/blender/*.py` in this repo | Project-owned |
| Materials | Principled BSDF, values in `continua_lib.py` | Project-owned |
| Environment lighting | Procedural `Lightformer`s — no HDRI file | n/a |
| Fonts | System font stacks only — no webfont is fetched | n/a |

Nothing is downloaded at build time or at runtime. The app works offline.

Total runtime download: **2.28 MB**, uncompressed, no textures (all materials
are untextured PBR, which is why there are only 6 textures in the whole scene —
they come from the environment map, not from files).

Draco compression is wired up in `export_glb(draco=True)` but is **off**: it
would trade ~40 % of the file size for a decoder download and a decompression
pass, which is the wrong trade at 2.3 MB total.

## 3. Editable sources

| File | Bytes | Regenerate with |
| --- | --- | --- |
| `assets/blender/continua_rover.blend` | 522,473 (510 KB) | `npm run blender:vehicle` |
| `assets/blender/continua_props.blend` | 193,715 (189 KB) | `npm run blender:props` |

`npm run blender:all` runs vehicle, props and preview renders in sequence.
Generation is headless (`--background --factory-startup`), so it never touches
an interactive Blender session and produces identical output on any machine
with the same Blender version. Built and verified with **Blender 5.2.0 LTS**.

No file in this repository is large enough to need Git LFS (largest tracked
file: 1.59 MB, `assets/reference/continua-dashboard-light.png`). The checkpoint
supervisor refuses anything above 45 MB that is not LFS-tracked, and warns above
5 MB.

## 4. Orientation contract

This is the part that silently breaks if it is not written down.

### Blender (authoring)

* Units: **metres**, scale 1.0.
* Axes: **Z-up**. Vehicle **forward = +X**, **left = +Y**, **up = +Z**.
* Vehicle root `CONTINUA_Vehicle` is an Empty at the **tyre contact plane**,
  world origin. Wheel centres sit at z = 0.405 (the tyre radius).
* Wheel objects have their origin at the **wheel centre**, axle along **Y**.
* Steering pivots `CONTINUA_Steer_FL/FR` are Empties at the wheel centre; the
  wheel is their child at local (0, 0, 0).

### glTF (runtime)

The exporter converts Z-up → Y-up as `gltf.x = blender.x`, `gltf.y = blender.z`,
`gltf.z = -blender.y`. Therefore, in the runtime asset:

| Quantity | Axis |
| --- | --- |
| Forward | **+X** |
| Up | **+Y** |
| Wheel spin | rotation about the wheel's local **Z** |
| Steering | rotation about the pivot's local **Y** |
| Vehicle yaw | rotation about world **Y**; `0` faces `+X` |

`packages/scene/src/components/Rover.tsx` applies exactly this, and
`tests/scene.spec.ts` asserts that wheel angle equals `distance / 0.405`.

A note on parenting: the Blender scripts set an explicit local offset with an
identity `matrix_parent_inverse` rather than `parent.matrix_world.inverted()`.
In background mode `matrix_world` is stale until the depsgraph is evaluated, and
that idiom silently doubles the child's offset — which is how the front wheels
first ended up 1.4 m in front of their arches.

## 8. Regeneration

```bash
npm run blender:vehicle    # .blend + hero .glb + LOD .glb
npm run blender:props      # .blend + props .glb
npm run blender:previews   # six studio renders
npm run blender:all        # all three, in order
```

`scripts/run-blender.mjs` finds Blender from `$CONTINUA_BLENDER`, then `PATH`,
then the usual Windows/macOS/Linux install locations, newest version first.
