# CONTINUA - asset manifest

Every model in this project is generated by a script in this repository. There
are no purchased or downloaded models, textures or HDRIs; the one texture, the
foliage atlas, is drawn by the build script itself. The one third-party
runtime file is the Draco mesh decoder (§2).

## 2. Runtime assets

Served from `apps/web/public/models/`. All three are Draco-compressed
(`KHR_draco_mesh_compression`, level 7; quantisation: position 14 bit, normal
10, colour 10, generic 12). The rover carries **no textures**: every material
is untextured PBR, surface detail is geometry, and contact darkening is the
baked AO below. The props carry one: the foliage atlas (1024 × 1024, lossless
WebP through `EXT_texture_webp`, 219 KB), shared by every leaf, blossom and
frond card (§2a).

| File | Bytes | Triangles | Contents |
| --- | --- | --- | --- |
| `continua_rover.glb` | 791,724 (773 KB) | 72,278 | Hero rover: 15 meshes (three of them moving sensors), 2 steering pivots, 24 materials |
| `continua_rover_lod1.glb` | 264,936 (259 KB) | 23,450 | Low-detail rover for the `low` quality tier |
| `continua_props.glb` | 1,502,208 (1467 KB) | 107,529 | 60 world props, instanced at runtime; the foliage atlas |

The three files total **2.56 MB**; the decoder adds `draco_decoder.wasm`
(192 KB) and `draco_wasm_wrapper.js` (58 KB).

**Cache busting.** `/models/*` is served `immutable` for a year
(`apps/web/next.config.ts`), so a re-export under the same name would never
reach a returning browser. Every export therefore rewrites
`packages/scene/src/components/modelVersions.ts` with a 12-character content
hash per file, and the URLs in `assets.ts` carry it as `?v=<hash>`. The hashes
are generated by `continua_lib.write_model_versions()` and must not be edited
by hand.

### Baked ambient occlusion

Each mesh carries a linear `FLOAT_COLOR` corner attribute named `AO`, exported
as `COLOR_0`; three.js multiplies it into the base colour. The raw Cycles bake is
remapped to `floor + (1 - floor) * ao^gamma` (floor 0.30-0.36 depending on the
asset) so a fully occluded crease keeps about a third of its colour instead of
reading as dirt.

* Rover statics are baked together against a ground plane: distance 0.55 m,
  floor 0.30, gamma 0.85.
* Wheels are baked **alone** (`occluders_only_self`; distance 0.22 m, floor
  0.35): they spin and steer, so their occlusion must not depend on where they
  were parked during the bake.
* World props are all authored at the origin, so each is baked alone against
  a shared 400 m ground plane (floor 0.36, gamma 0.85), with a per-prop AO
  distance (`AO_DISTANCE` in `build_props.py`).

### 2a. Foliage cards

Every crown, shrub, flowering bush, bedding plant and palm frond is built the
way real-time foliage is (`world_foliage.py`): small alpha-clipped quads
("cards"), each showing a spray of leaves, a cluster of five-petalled
blossom, or a pinnate frond from one shared atlas, arranged in ellipsoid
clusters round a coarse inner core that keeps the sky from showing through.

* **The atlas** is drawn with numpy from fixed seeds - leaves on twigs,
  blossom, a palm frond with two rows of leaflets - supersampled 2x and box
  filtered, with each leaf's tone bled into the transparent texels around it
  so filtering never fringes. It is grey; each card material's base-colour
  factor is its colour, and the AO bake its shading.
* **Normals** point out of each cluster's ellipsoid (blended 4:1 with the
  card's own facing), so a crown lights as one rounded mass, bright on top
  and on the sun side. In the browser a card seen from behind keeps that
  normal instead of flipping it (`WorldProps.tsx`, `tuneMaterial`).
* **Variety**: after the AO bake every card gets its own shade - lighter,
  darker, yellower, bluer - multiplied into `COLOR_0`.
* **Distance**: mipmaps average leaves into the gaps between them; the shader
  scales alpha back up with the mip level in the texture's least-minified
  direction, so far crowns stay full without turning edge-on cards solid.
* **Export**: `alphaMode: MASK` (cutoff 0.5) and `doubleSided`, from the node
  layout the glTF exporter recognises; texture coordinates are exported for
  the card meshes only.

The new planting is lighter than the old: 1,146 triangles for a broadleaf
tree against 3,346, 1,526 for a flame tree against 5,686.

No file in this repository is large enough to need Git LFS. The checkpoint
supervisor refuses anything above 45 MB that is not LFS-tracked, and warns above
5 MB.

## 4. Orientation contract

This is the part that silently breaks if it is not written down.

### Blender (authoring)

* Units: **metres**, scale 1.0.
* Axes: **Z-up**. Vehicle **forward = +X**, **left = +Y**, **up = +Z**.
* Vehicle root `CONTINUA_Vehicle` is an Empty at the **tyre contact plane**,
  world origin. Wheel centres sit at z = 0.405 (the tyre radius).
* Wheel objects have their origin at the **wheel centre**, axle along **Y**.
* Steering pivots `CONTINUA_Steer_FL/FR` are Empties at the wheel centre; the
  wheel is their child at local (0, 0, 0).
* Every prop is authored at the origin with its base on z = 0 and its **front
  facing +X**, unless §6 says otherwise.

### glTF (runtime)

The exporter converts Z-up → Y-up as `gltf.x = blender.x`, `gltf.y = blender.z`,
`gltf.z = -blender.y`. Therefore, in the runtime asset:

| Quantity | Axis |
| --- | --- |
| Forward | **+X** |
| Up | **+Y** |
| Wheel spin | rotation about the wheel's local **Z** |
| Steering | rotation about the pivot's local **Y** |
| Vehicle yaw | rotation about world **Y**; `0` faces `+X` |

`packages/scene/src/components/Rover.tsx` applies exactly this, and
`tests/scene.spec.ts` asserts that wheel angle equals `distance / 0.405`.

A note on parenting: the Blender scripts set an explicit local offset with an
identity `matrix_parent_inverse` rather than `parent.matrix_world.inverted()`.
In background mode `matrix_world` is stale until the depsgraph is evaluated, and
that idiom silently doubles the child's offset - which is how the front wheels
first ended up 1.4 m in front of their arches.

## 7. Preview renders

`assets/previews/` - Blender EEVEE studio renders of the rover, generated by
`npm run blender:previews`:

`rover_front.png`, `rover_side.png`, `rover_rear.png`,
`rover_threequarter.png`, `rover_detail_front.png`, `rover_detail_wheel.png`

`assets/previews/browser/` - real browser captures at 1920×1080, deterministic
by timestamp: the `view-*` set is `tests/evidence.spec.ts`'s inspection set
(same times, cameras and settings) rendered on the GPU at the high tier by
`node scripts/scene-shots.mjs --set evidence`, because the test project draws
with SwiftShader and so starts on the low tier.

`scripts/scene-shots.mjs` captures a fixed set of `/scene-lab` views at given
clock times through `window.__CONTINUA__`, for before/after comparison.

A Blender render is not evidence that an export is correct. The browser captures
and the rig-integrity test are.

## 8. Regeneration

```bash
npm run blender:vehicle    # .blend + hero .glb + LOD .glb + model hashes
npm run blender:props      # .blend + props .glb + model hashes
npm run blender:previews   # six studio renders
npm run blender:all        # all three, in order
```

`scripts/run-blender.mjs` finds Blender from `$CONTINUA_BLENDER`, then `PATH`,
then the usual Windows/macOS/Linux install locations, newest version first.
